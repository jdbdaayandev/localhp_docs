Developer documentation

Build locally.
Understand every layer.

LocalPHP is a lightweight PHP framework designed for local application development. This guide covers the project structure, HTTP layer, routing, custom views, database tools, validation, sessions, and CLI commands present in the current source.

PHP 8.2+Composer / PSR-4MySQL / PDOCustom PHP templatesLocal development focus
Version note. The inspected source identifies itself as LocalPHP 0.2.0 and is actively evolving. This documentation describes the source snapshot it accompanies; confirm behavior against your current working copy if you have made later changes.

1. Requirements

PHP 8.2 or newer

The Composer project requires PHP ^8.2.

Composer

Used for PSR-4 autoloading and helper-file loading.

Local server

Laragon/Apache is the primary documented setup. MySQL is needed for database features.

Ensure PHP has PDO and the MySQL PDO driver enabled. The database implementation currently accepts the mysql driver.

2. Installation and first run

Install dependencies

Open a terminal in the project root:

composer install
composer dump-autoload
php local list

Configure environment

Create or update the root .env file. Example values for a local Laragon installation:

APP_NAME=LocalPHP
APP_ENV=local
APP_DEBUG=true
APP_URL=http://localhost/localphp
APP_TIMEZONE=Asia/Manila

DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=localphp
DB_USERNAME=root
DB_PASSWORD=
DB_CHARSET=utf8mb4

SESSION_NAME=localphp_session
SESSION_LIFETIME=120
SESSION_PATH=/
SESSION_DOMAIN=
SESSION_SECURE=false
SESSION_SAME_SITE=Lax

Change APP_URL and database credentials to match your machine. Create the database in MySQL before running migrations.

Open the application

Start Apache in Laragon and browse to the configured URL, commonly http://localhost/localphp/. Start MySQL when using database features.

Local-only settings. The sample enables debug mode and uses example credentials. Do not expose a debug-enabled development installation publicly, and never commit real secrets.

4. Application bootstrap and request lifecycle

The root entry point loads Composer, boots the app, captures an HTTP request, asks the application to handle it, and sends the resulting response.

// bootstrap/app.php
<?php
declare(strict_types=1);

use LocalPHP\Application;

$app = new Application(basePath: dirname(__DIR__));
return $app;
// index.php
require_once __DIR__ . '/vendor/autoload.php';
$app = require __DIR__ . '/bootstrap/app.php';
$request = LocalPHP\Http\Request::capture();
$response = $app->handle($request);
$response->send();

The application initializes environment/configuration, core services, and route loading. Route definitions are loaded from routes/web.php. The request is matched by the router and translated into a response.

5. Environment and configuration

Environment values

The environment loader reads the root .env file and exposes values through env(). The loader handles common quoted values, comments, basic value normalization, and variable interpolation. Keep credentials outside committed source.

$environment = env('APP_ENV', 'local');
$debug = env('APP_DEBUG', true);
$database = env('DB_DATABASE', 'localphp');

Configuration files

Application settings live in config/*.php. Use dot notation with config() to retrieve a nested value:

$appName = config('app.name', 'LocalPHP');
$defaultConnection = config('database.default', 'mysql');

The configuration helper can read the generated storage/cache/config.php file if present. Regenerate it after changing configuration values.

Timezone

Set APP_TIMEZONE to a valid PHP timezone identifier, such as Asia/Manila.

6. Routing

Define routes in routes/web.php. The route file receives the bootstrapped $app variable. Retrieve the router with $app->router().

Basic routes

<?php
declare(strict_types=1);

use App\Controllers\HomeController;

$router = $app->router();

$router->get('/', [HomeController::class, 'index']);
$router->get('/hello', fn () => 'Hello from LocalPHP!');
$router->get('/hello/{name}', function ($request, $name) {
    return "Hello, {$name}!";
});

Available route methods

MethodUse
get($uri, $action)Register GET route.
post($uri, $action)Register POST route.
put($uri, $action)Register PUT route.
patch($uri, $action)Register PATCH route.
delete($uri, $action)Register DELETE route.
any($uri, $action)Register a route for supported methods.
group($attributes, $callback)Register grouped routes with attributes such as prefixes.
urlFor($name, $parameters = [])Generate a URL for a named route.

Named routes

$router->get('/products/{id}', [ProductController::class, 'show'])
    ->name('products.show');

$url = $router->urlFor('products.show', ['id' => 12]);

Route names and URI parameters are handled by the current Route and Router classes. Check the implementation for edge cases before depending on advanced grouping or middleware behavior.

7. Controllers

Controllers belong in app/Controllers/ under the App\Controllers namespace. An HTTP controller action should return a response, commonly by rendering a view.

<?php
declare(strict_types=1);

namespace App\Controllers;

use LocalPHP\Http\Response;

final class HomeController
{
    public function index(): Response
    {
        return view('home', [
            'title' => 'Welcome to LocalPHP',
        ]);
    }
}

Keep request-specific coordination in controllers and put reusable domain logic in services or models. The current generator is php local make:controller Home.

8. HTTP requests and responses

Request access

The LocalPHP\Http\Request object wraps request information instead of having every controller read PHP superglobals directly.

$request->method();
$request->uri();
$request->query('page', 1);      // query-string value
$request->input('email');       // submitted input
$request->file('avatar');       // uploaded file entry
$request->cookie('theme');
$request->server('REQUEST_TIME');
$request->isMethod('POST');

Convenience methods include isGet(), isPost(), isPut(), and isDelete(). Verify the exact distinction between query and input data in the current request implementation before relying on it for security-sensitive checks.

Responses

return response('Created', 201);
return response(['ok' => true, 'count' => 3]);
return response('<h1>Not found</h1>', 404, [
    'Content-Type' => 'text/html; charset=UTF-8',
]);

return redirect(url('login'));

Response exposes content(), statusCode(), status($code), header($name, $value), headers(), and send(). The helper serializes supported response content; check the helper source for its exact content-type behavior.

9. Views and the template engine

View files live in resources/views/. The helper convention maps dot notation to nested directories: view('home') resolves resources/views/home.php, while view('layouts.app') resolves resources/views/layouts/app.php.

Render a view

return view('home', [
    'title' => 'Products',
    'products' => $products,
]);

Layout example

<!-- resources/views/layouts/app.php -->
<!doctype html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>@yield('title', 'LocalPHP')</title>
</head>
<body>
  <main>@yield('content')</main>
</body>
</html>

Template directives

@extends('layouts.app')Choose a layout.

11. Sessions and flash messages

The session manager supports reading, writing, checking, pulling, forgetting, flushing, regenerating, destroying, and flash data. The helpers include session() and flash().

// Read and write session data
$count = session('count', 0);
session()->put('count', $count + 1);

// Flash data for the next request
flash('success', 'Saved successfully!');

// Access flash data through the session manager
$message = session()->getFlash('success');

Example session configuration keys include SESSION_NAME, SESSION_LIFETIME, SESSION_PATH, SESSION_DOMAIN, SESSION_SECURE, and SESSION_SAME_SITE. Use HTTPS and secure cookie settings in any HTTPS deployment. Session behavior depends on PHP session configuration and when the manager starts the session.

12. Input validation

Validate data

$data = validate($request->input(), [
    'name' => 'required|string|min:2|max:100',
    'email' => 'required|email',
    'age' => 'nullable|integer|min:18',
]);

For non-throwing control flow, use a validator instance:

$validator = validator($input, [
    'email' => 'required|email',
]);

if ($validator->fails()) {
    $errors = $validator->errors();
    $firstMessage = $validator->first('email');
} else {
    $safeData = $validator->validated();
}

Implemented rule names in the current source

required, nullable, sometimes, string, integer, numeric, boolean, array, email, url, alpha, alpha_num, alpha_dash, min, max, between, in, not_in, confirmed, same, different, date, date_format, regex, accepted, digits, uuid, json, unique, and exists.

Database-backed rules. unique and exists need a working configured database. Validate data on the server even when client-side validation is present.

Reusable validator classes can be generated with php local make:validator User. The generator provides a rules method scaffold; connect the validator to the relevant controller/action yourself.

13. Database connection

LocalPHP's database layer uses PDO and currently supports MySQL/MariaDB-style connections. The connection uses exception mode, associative fetches, and native prepared statements by default.

// config/database.php should match your environment
return [
    'default' => env('DB_CONNECTION', 'mysql'),
    'connections' => [
        'mysql' => [
            'driver' => 'mysql',
            'host' => env('DB_HOST', '127.0.0.1'),
            'port' => env('DB_PORT', 3306),
            'database' => env('DB_DATABASE', 'localphp'),
            'username' => env('DB_USERNAME', 'root'),
            'password' => env('DB_PASSWORD', ''),
            'charset' => env('DB_CHARSET', 'utf8mb4'),
        ],
    ],
];

Use the global db() helper for the manager or the static LocalPHP\Database\DB entry point. Database creation is lazy in the CLI so commands that do not need the database can run without an active MySQL server.

use LocalPHP\Database\DB;

$users = DB::table('users')
    ->where('active', 1)
    ->orderBy('name')
    ->get();

Transactions

DB::transaction(function ($connection) {
    // Perform related database operations here.
});

The facade also exposes beginTransaction(), commit(), rollBack(), connection(), and disconnect(). Prefer the transaction callback when it fits the operation.

14. Query builder reference

Start with DB::table('table_name') or a model's query() method. Builder calls are chainable. Values should be passed through builder parameters instead of concatenated into SQL.

Selecting and retrieving

$rows = DB::table('products')->select('id', 'name', 'price')->get();
$product = DB::table('products')->where('id', 10)->first();
$product = DB::table('products')->find(10);
$names = DB::table('products')->pluck('name');
$price = DB::table('products')->where('id', 10)->value('price');
$count = DB::table('products')->count();

Filters and conditions

Supported methods include where, orWhere, whereColumn, whereIn, orWhereIn, whereNotIn, orWhereNotIn, whereBetween, orWhereBetween, whereNotBetween, orWhereNotBetween, whereNull, orWhereNull, whereNotNull, orWhereNotNull, whereDate, whereTime, whereYear, whereMonth, whereDay, whereLike, whereNotLike, whereRaw, orWhereRaw, whereNested, whereExists, orWhereExists, whereNotExists, and orWhereNotExists.

$products = DB::table('products')
    ->where('active', 1)
    ->where(function ($query) {
        $query->where('stock', '>', 0)
              ->orWhere('allow_backorder', 1);
    })
    ->get();

Joins, grouping, ordering

Join methods: join, leftJoin, rightJoin, crossJoin, joinSub, leftJoinSub. Grouping and aggregation methods include groupBy, groupByRaw, having, orHaving, havingRaw, sum, avg, min, max, exists, and doesntExist.

$totals = DB::table('order_items')
    ->select('product_id')
    ->selectRaw('SUM(quantity * unit_price) AS total')
    ->groupBy('product_id')
    ->having('total', '>', 1000)
    ->get();

Ordering and pagination-style limits

Use orderBy, orderByDesc, orderByRaw, latest, oldest, inRandomOrder, limit, take, offset, skip, and forPage.

Writes

DB::table('products')->insert([
    'name' => 'Spark Plug',
    'price' => 150.00,
]);

DB::table('products')->where('id', 10)->update([
    'price' => 175.00,
]);

DB::table('products')->where('id', 10)->delete();

The builder also provides insertGetId, upsert, increment, decrement, conditional chaining via when and unless, raw expressions, and SQL/binding inspection through toSql() and getBindings(). Confirm method signatures in framework/src/Database/QueryBuilder.php for less common operations.

Raw SQL caution. Bind user-controlled values. Raw SQL fragments and identifier names are not interchangeable with bound values. Never interpolate untrusted input directly into a raw SQL string.

15. Models / ORM

Models extend LocalPHP\Model\Model. Set the table explicitly when needed and define mass-assignable fields with $fillable.

<?php
declare(strict_types=1);

namespace App\Models;

use LocalPHP\Model\Model;

final class Product extends Model
{
    protected string $table = 'products';
    protected array $fillable = ['name', 'sku', 'price', 'stock'];
}

Common operations

$all = Product::all();
$product = Product::find(1);
$matching = Product::where('active', 1)->get();
$count = Product::count();

$product = Product::create([
    'name' => 'Brake Pad',
    'sku' => 'BP-001',
    'price' => 350,
    'stock' => 12,
]);

$product->price = 375;
$product->save();
$product->delete();

Model methods include query, all, find, where, orderBy, create, firstOrCreate, count, fill, getAttribute, setAttribute, getAttributes, toArray, save, delete, exists, getTable, and getKeyName.

ORM scope. This is a lightweight custom ORM, not a feature-complete Active Record package. Do not assume relationships, eager loading, scopes, events, casts, or soft-delete filtering exist unless present in the source.

16. Schema builder and migrations

Schema builder

LocalPHP\Database\Schema supports creating, altering, and dropping MySQL tables from PHP code.

use LocalPHP\Database\Schema;
use LocalPHP\Database\Blueprint;

Schema::create('products', function (Blueprint $table): void {
    $table->id();
    $table->string('name', 150);
    $table->string('sku', 60);
    $table->decimal('price', 10, 2);
    $table->integer('stock')->default(0);
    $table->timestamps();
    $table->unique('sku');
});

Column helpers in the current source include id, bigIncrements, increments, string, char, text, mediumText, longText, integer, bigInteger, tinyInteger, boolean, decimal, float, double, date, dateTime, timestamp, json, timestamps, and softDeletes. Index helpers include index, unique, primaryKey, and foreign. Column options are defined by ColumnDefinition; inspect that class for supported modifiers.

Migration class

Migration files are stored in database/migrations/ and use LocalPHP\Database\Migration:

use LocalPHP\Database\Migration;
use PDO;

return new class extends Migration {
    public function up(PDO $pdo): void
    {
        $pdo->exec('CREATE TABLE example (id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY)');
    }

    public function down(PDO $pdo): void
    {
        $pdo->exec('DROP TABLE IF EXISTS example');
    }
};

Generate a migration with php local make:migration create_products_table, then edit its up() and down() methods to define the schema.

Destructive commands. php local migrate:fresh --force drops and recreates migration-managed tables. Use only when you intend to reset the database and have a backup if the data matters.

17. Seeders

Seeders populate development or test data. The base class is LocalPHP\Database\Seeder, which defines run(PDO $pdo): void.

use LocalPHP\Database\Seeder;
use PDO;

final class ProductSeeder extends Seeder
{
    public function run(PDO $pdo): void
    {
        $statement = $pdo->prepare(
            'INSERT INTO products (name, sku) VALUES (?, ?)'
        );
        $statement->execute(['Spark Plug', 'SP-001']);
    }
}

Generate a seeder with php local make:seeder ProductSeeder and run the default or a named seeder with php local db:seed or php local db:seed ProductSeeder.

19. Cache, errors, and logs

Configuration cache

Configuration caching is implemented through a generated PHP file, not a general-purpose data cache:

php local config:cache
php local config:clear

The runtime configuration helper reads storage/cache/config.php when present. Rebuild the cache after changing configuration files or values that are baked into the cache.

Exception logs

The web exception handler registers PHP error, uncaught exception, and shutdown handling. It writes exception details to a daily file such as storage/logs/localphp-YYYY-MM-DD.log and falls back to PHP's error_log() if writing fails. When debug mode is disabled, the web exception page is intended to hide detailed exception information from visitors.

Implemented in source: configuration-file caching and web exception logging.
Not the same as a complete cache/logger service. The current source does not establish a general cache API with TTL/invalidation for arbitrary application data, nor a verified logger facade with methods such as logger()->info(). Route caching is not documented as available.

20. Security practices

  • Keep .env out of version control and ensure the web server denies direct access to it.
  • Set APP_DEBUG=false on publicly reachable deployments.
  • Use query-builder parameters or PDO prepared statements for values; do not concatenate user input into SQL.
  • Escape user-controlled output. Use raw template output only for trusted/sanitized HTML.
  • Validate every incoming request on the server.
  • Use allowlists for mass assignment through model $fillable settings.
  • Use HTTPS and secure session cookie settings where HTTPS is available.
  • Confirm CSRF token validation is actually applied to state-changing routes; token-generation helpers alone do not prove enforcement.
  • Verify the storage directory is not publicly readable by the configured web server.
  • Back up data before running destructive migration commands.
Deployment readiness. LocalPHP is a lightweight framework in active development. Treat public production use as requiring a separate security review, integration tests, correct document-root setup, and verification of middleware/CSRF behavior.

21. Troubleshooting

Composer class not found

composer dump-autoload

Check namespace and file path. LocalPHP\ maps to framework/src/; App\ maps to app/.

404 - Page Not Found

  • Confirm the route exists in routes/web.php.
  • Check the HTTP method and URI, including any subfolder/base path.
  • Check that the web server points to the expected project entry point and rewrite rules are enabled.
  • Ensure the application boots and route definitions load successfully.

MySQL connection refused

  • Start MySQL in Laragon.
  • Verify host, port, database name, username, and password in .env.
  • Create the database before migrations.
  • Ensure the PDO MySQL extension is enabled in the PHP version used by both Apache and CLI.

View not found

Check that the view exists under resources/views/ and the name matches the file path. For example, view('home') maps to resources/views/home.php.

Configuration changes seem ignored

php local config:clear
php local config:cache

Clear the cache first when testing uncached values. Rebuild it after final changes if you want cached configuration enabled.

Log file missing

Trigger an error only in a safe local test, then check storage/logs/. Verify that the directory is writable by the PHP process. If the log write fails, the handler attempts to use PHP's error log.
